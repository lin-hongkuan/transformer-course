第 3 章 · 注意力机制

注意力机制：让词和词互相"看一眼"

这是全书最重要的一章。Transformer 的全部魔力，来自一个叫"注意力（Attention）"的操作。本章用"图书馆查书"的类比建立直觉，然后用 3 个词、每个词 2 个数字的最小例子，把原论文公式 Attention(Q,K,V)=softmax(QKᵀ/√d_k)V 里的每一步都亲手算一遍。读完这一章，你就握住了现代大语言模型的心脏。

3.1 从"读句子"说起：为什么词需要互相看

回想第 1 章的结论：RNN 像传话游戏，词要一个接一个排队处理，远处的信息传着传着就丢了。而第 2 章告诉我们：每个词已经被表示成一个向量（一串数字），比如词嵌入加上位置编码之后，"猫"这个向量里既有"猫"的语义，也有"我在第 3 个位置"的信息。

但光有这些还不够。看这句中文：

我把它放在桌上，因为它太重了

句子里两个"它"指的是什么？人读这句话时，眼睛会不自觉地往回瞟，去寻找"它"指代的对象。也就是说，理解一个词，需要去看句子里的其他词。词与词之间需要一种直接对话的机制——不用排队传话，任何一个词都可以直接"看一眼"任何另一个词，并决定看多重。

再看几个例子，体会"词的新表示必须依赖上下文"这件事有多普遍：

  • "苹果发布了新手机" vs "我吃了一斤苹果"——同一个词，前一句该多关注"发布""手机"，后一句该多关注"吃""一斤"。词义要靠邻居来锁定。
  • "小明给小红一本书，她很开心"——"她"是谁？必须回头找到"小红"。这种指代关系可能隔着好几个词，RNN 传话传到"她"时早就模糊了。
  • "他差点没摔倒"——"差点"和"没"组合起来意思反转，单个词的向量完全看不出这种化学反应。

这个机制就是注意力（Attention）。它的核心思想一句话就能说完：

注意力的一句话定义

每个词拿着自己的"问题"去和句子里的每一个词（包括自己）的"标签"比对，算出相关度；然后按相关度为权重，把所有词的"内容"加权混合起来，得到这个词的新表示。

"问题""标签""内容"这三样东西，就是大名鼎鼎的 Query、Key、Value。下面先建立直觉，再上公式，再上数字。

3.2 直觉类比：在图书馆里查资料

想象你走进一座巨大的图书馆，想搞懂一个问题。整个过程分四步：

  1. 你心里有一个问题：比如"猫科动物的驯化历史"。这就是 Query（查询向量）。
  2. 每本书的书脊上贴着标签：写着这本书的关键词，比如"猫的考古""狗的饲养""微积分入门"。这就是 Key（键向量）。
  3. 书的内容本身：标签只是用来检索的，真正有价值的是书页里的文字。这就是 Value（值向量）。
  4. 你不可能把全馆的书都精读一遍：你把问题跟每本书的标签比对，越匹配的书分越高；然后按分数为比例，从各本书里"抽取"内容——最相关的那本抽 40%，次相关的抽 30%，完全无关的微积分教材抽 0%。抽出来的内容混合在一起，就是你这趟图书馆之行带走的"答案笔记"。

把注意力机制逐项对照进去：

图书馆里的角色注意力里的角色本质
你心里的问题Query（查询）"我想找什么样的信息"
书脊上的标签Key（键）"我能提供什么线索，用来被检索"
书的实际内容Value（值）"我真正携带的信息，用来被取走"
问题与标签的匹配分注意力分数（点积）相关度的度量
按分数分配的阅读比例注意力权重（softmax 之后）一组和为 1 的百分比
混合后的答案笔记注意力输出Value 的加权和

还有一个类比同样好使：查字典。你拿着一个字（Query）去翻字典，字典里每个词条的词头（Key）用来定位，词条下的解释（Value）才是你取走的内容。数据库的键值查询、搜索引擎的检索，全是同一个套路。注意力的本质就是"可微分的软查询"：字典查询是找到唯一一个词条，注意力是对所有词条按相关度分配比例、混合取内容——因为神经网络需要每一步都能求导，所以必须"软"，不能"只选一本"。

为什么要"软"查询？（提前剧透第 7 章）

如果注意力是"只选相关度最高的那一个词"，那它就像一个二选一开关：选 A 还是选 B。训练时（见第 7 章）模型需要知道"如果多给 B 一点关注，结果会变好还是变坏"——这就是梯度。但开关式的硬选择没有梯度可言：你没法对"选/不选"求导。软查询把所有词都留了一份比例，任何比例的微小调整都会平滑地影响输出，梯度才能一路流回每个词的向量，模型才学得动。这是整个深度学习里反复出现的套路：凡是需要学习的选择，都要做成软的、可微的。

先记住这个画面，后面的所有公式都只是把它翻译成数学：提问（Q）→ 对标签（K）→ 按匹配度分比例（softmax）→ 按比倒内容（V）→ 混合带走（输出）。

3.3 Q、K、V 从哪来：同一个向量，三张面孔

一个反直觉但极其重要的事实：Q、K、V 不是三份不同的数据，它们全都来自同一个输入。

设句子有 n 个词，每个词经过嵌入层（见第 2 章）得到一个 d_model 维向量。把所有词向量堆起来，就是输入矩阵 X，形状是 [n × d_model]。然后模型里存着三个可学习的权重矩阵 WQ、WK、WV（训练时自动学出来的），做三次矩阵乘法：

Q = XWQ     K = XWK     V = XWV

打个比方：同一个词，像同一个员工，戴上三顶不同的帽子。当它戴着 Query 帽时，它负责"提问"——"我需要什么样的信息来理解自己？"；戴着 Key 帽时，它负责"自我宣传"——"我身上有这些特征，谁需要就来找我"；戴着 Value 帽时，它负责"交付货物"——"如果被选中，我就把这些内容交出去"。三个权重矩阵就是三顶帽子，把同一个词向量投影成三种角色。

用数字感受一下规模。原论文的 base 模型里 d_model = 512，而每个注意力头（"头"的概念见第 4 章，本章先按单头理解）有 d_k = d_v = 64。一个 10 词的句子：

张量形状怎么来的含义
X[10 × 512]嵌入 + 位置编码（第 2 章）10 个词，每个 512 维
WQ、WK[512 × 64]训练学出来的参数"提问帽"和"标签帽"
Q = XWQ[10 × 64]矩阵乘法10 个词各自的提问向量
K = XWK[10 × 64]矩阵乘法10 个词各自的标签向量
V = XWV[10 × 64]矩阵乘法10 个词各自的内容向量

在原论文的设定里（d_model=512、单头时 d_k=d_v=64），一个 10 词的句子会经历这样的形状变化：

为什么偏要分三个角色？

你可能会问：既然都来自 X，直接拿 X 互相比不行吗？可以，但表达能力会差很多。原因有二：其一，"我是谁"和"我想找什么"是两回事——代词"它"的内容很贫乏，但它的 Query 必须学会表达"我在找一个名词"；如果 Query 和 Value 共用同一个向量，这两个任务就互相掣肘。其二，三个权重矩阵给了模型三组可学习的自由度，训练可以分别调整"怎么提问""怎么宣传""交付什么"，而不必妥协。这和数据库把"索引键"与"存储内容"分开设计是同一个道理。

3.4 热身：softmax 复习

注意力里有一个关键工具：softmax。它的任务是把任意一组实数变成一组"和为 1 的百分比"，而且保持大小关系——原来大的，出来还是大。

直觉：softmax 先做两件简单的事。第一步，对每个数取指数 eˣ。指数函数有两个好性质：任何数取完指数都变成正数；而且它会放大差距——2 和 1 只差 1，但 e²≈7.39 是 e¹≈2.72 的 2.7 倍。第二步，把每个指数除以所有指数之和，强行让总和等于 1。

softmax(xi) = exi / Σj exj

手算一遍，用三个分数 2, 1, 0：

输入 xeˣ（取指数）除以总和 11.1073softmax 输出
2e² = 7.38917.3891 / 11.10730.6652
1e¹ = 2.71832.7183 / 11.10730.2447
0e⁰ = 1.00001.0000 / 11.10730.0900
合计（指数之和 = 7.3891 + 2.7183 + 1.0000 = 11.1073）1.0000 ✓

三个输出 0.6652、0.2447、0.0900 都在 0 到 1 之间，加起来正好等于 1，而且大小顺序和输入一致。这就是注意力需要的"权重"。指数带来的放大效应也很明显：第一名拿走了约 66.5%，是第二名（约 24.5%）的近三倍，而原始分数只差 1。分数差距越大，softmax 越接近"赢家通吃"——这一点在 3.6 节讲 √d_k 时还会回来。

工程细节：为什么代码里先减最大值

实际实现里，softmax 会先对每个输入减去这一行的最大值再取指数：softmax(xᵢ) = e^{xᵢ−m} / Σ e^{xⱼ−m}，其中 m = max(x)。数学上结果完全相同（分子分母同除 eᵐ），但可以防止分数很大时 eˣ 溢出计算机的浮点范围。本章手算的数字都很小，不需要这一招；下面的演示代码里也隐含了同样的处理。你知道有这么个"数值稳定化"技巧即可。

3.5 灵魂手算：3 个词的完整注意力

现在做本章最重要的事：把注意力的每一步用真实数字算出来。为了让你能拿着纸笔跟上，我们把规模缩到最小：

  • 句子只有 3 个词：「我 爱 猫」；
  • 每个词的 Q、K 向量只有 2 维（d_k = 2），V 向量也只有 2 维（d_v = 2）；
  • 真实模型里这些向量由 XWQ 等矩阵乘法得到（3.3 节），这里我们直接给出算好的 Q、K、V，专注于注意力本身的计算。

先看"剧本"全貌，再逐幕演出：

QKᵀ → 除以 √d_k → softmax → 得到权重矩阵 A → A 乘 V → 输出 O

第 0 步：给出 Q、K、V 的具体数值

下面就是本例的全部输入。每一行是一个词的向量（你可以把它理解成 3.3 节的矩阵乘法已经算完的结果）。数字是手工挑选的，目的是让点积好算、且三行三个词能展现出三种不同的关注模式：

词Query（提问）Key（标签）Value（内容）
我(1, 0)(1, 0)(1, 0)
爱(0, 1)(0.5, 1)(0, 1)
猫(1, 1)(0.6, 0.5)(1, 1)

写成矩阵（每行一个词，共 3 行）：

Q = [[1,0],[0,1],[1,1]]    K = [[1,0],[0.5,1],[0.6,0.5]]    V = [[1,0],[0,1],[1,1]]

第 1 步：计算 QKᵀ —— 每个 Query 和每个 Key 做点积

点积复习（预备知识，见第 0 章）：两个向量对应位置相乘再相加，例如 (1, 0) · (0.5, 1) = 1×0.5 + 0×1 = 0.5。点积越大，两个向量方向越一致，直觉上就是"问题和标签越匹配"。

为什么是点积而不是别的？可以从几何上理解：两个向量的点积等于它们的长度乘以夹角的余弦。方向越一致的向量，点积越大；垂直的点积为 0；反向的为负。用它来度量"Query 想要的方向"和"Key 宣称的方向"有多一致，再自然不过。而且点积只是一堆乘加，GPU 算起来飞快。

矩阵乘法 QKᵀ 的第 i 行第 j 列，就是"第 i 个词的 Query"点乘"第 j 个词的 Key"。Kᵀ 是 K 的转置（行列互换），目的是让"每个 Q 行向量"能和"每个 K 行向量"两两点积。逐个算：

  • 我→我：(1,0)·(1,0) = 1×1 + 0×0 = 1.0；我→爱：(1,0)·(0.5,1) = 0.5 + 0 = 0.5；我→猫：(1,0)·(0.6,0.5) = 0.6 + 0 = 0.6
  • 爱→我：(0,1)·(1,0) = 0 + 0 = 0.0；爱→爱：(0,1)·(0.5,1) = 0 + 1 = 1.0；爱→猫：(0,1)·(0.6,0.5) = 0 + 0.5 = 0.5
  • 猫→我：(1,1)·(1,0) = 1 + 0 = 1.0；猫→爱：(1,1)·(0.5,1) = 0.5 + 1 = 1.5；猫→猫：(1,1)·(0.6,0.5) = 0.6 + 0.5 = 1.1
原始分数 QKᵀK：我K：爱K：猫
Q：我1.00.50.6
Q：爱0.01.00.5
Q：猫1.01.51.1

先读一眼这张表（softmax 之前就能读出趋势）："我"最关注自己（1.0）；"爱"最关注自己（1.0），对"我"毫无兴趣（0.0）；"猫"对三者都有兴趣，最喜欢"爱"（1.5）。

第 2 步：除以缩放因子 √d_k

本例 d_k = 2，所以 √d_k = √2 ≈ 1.4142。把上面每个数除以 1.4142（为什么必须除，下一节专门讲）：

第 3 步：对每一行做 softmax，得到注意力权重矩阵 A

对每一行（每个 Query 那一行）单独做 softmax。以第 1 行（"我"的视角）为例，输入是 (0.7071, 0.3536, 0.4243)：

  • 取指数：e0.7071 = 2.0281，e0.3536 = 1.4242，e0.4243 = 1.5285

读法：第 3 行是说，"猫"把自己 40.72% 的注意力给了"爱"，30.69% 给了自己，28.59% 给了"我"。每个词的"注意力预算"恰好是 100%。

最后一步，用权重去混合 Value。O = AV，第 i 行的输出 = A 第 i 行的三个权重分别乘三个词的 V 向量再相加。逐词算：

爱 的新表示0.2246×(1,0) + 0.4555×(0,1) + 0.3199×(1,1)(0.2246+0.3199, 0.4555+0.3199) = (0.5445, 0.7754)

完工。每个词的新表示都是全句 Value 的加权和——"我"的新向量里混进了"爱"和"猫"的内容。这就是"上下文相关的词表示"：同一个词在不同句子里，因为注意力权重不同，输出向量也不同。至此，你已经完整手算了一遍缩放点积注意力。

回头看，整个机制其实只用了三种运算：矩阵乘法、除以一个常数、逐行 softmax——没有循环、没有分支、没有任何"排队等前一个词"。这正是它能在 GPU 上飞速并行的原因，也是它能取代 RNN 的工程基础。

亲手验证一下

拿纸笔把"爱"那一行重算一遍：0.2246×1 + 0.4555×0 + 0.3199×1 = 0.5445，0.2246×0 + 0.4555×1 + 0.3199×1 = 0.7753 ≈ 0.7754（末位差是四舍五入造成的）。如果你算出来的数和表里一致，说明你已经真正掌握了这个机制。

3.6 为什么要除以 √d_k？

公式里那个 √d_k 看起来不起眼，却关系到模型能不能训练起来。论证分两步：先看点积本身有多大，再看大数字对 softmax 做了什么。

第一步：点积的方差随维度线性增长。假设 q 和 k 各有 d_k 个分量，每个分量都是均值为 0、方差为 1 的独立随机数。点积 q·k = Σ qᵢkᵢ 是 d_k 个乘积之和。每个乘积 qᵢkᵢ 的方差是 1（两个方差为 1 的独立变量之积的方差仍为 1），独立变量相加时方差直接相加，所以：

Var(q·k) = d_k   ⇒   标准差 = √d_k

也就是说，维度越大，点积的"典型大小"就越大，大约按 √d_k 的尺度膨胀。用具体数字感受一下这个膨胀有多快：

d_k√d_k点积分数的典型波动幅度后果
2（本章手算例）1.41±1.4 左右几乎没影响
64（原论文）8±8 左右softmax 明显变尖锐
512（d_model）22.6±23 左右权重趋近 one-hot
10000（假想）100±100 量级softmax 完全饱和

把点积除以 √d_k，恰好把这个膨胀抵消掉，让任何维度下缩放后的分数方差都回到 1 左右。

第二步：大分数会把 softmax 推进"饱和区"，梯度消失。回忆 3.4 节：softmax 会放大差距。当输入分数都很温和时，它输出一组均衡的权重；当输入分数巨大时，它会变成"赢家通吃"——最大的那个拿走几乎全部权重。看对比：

三个原始分数不缩放直接 softmax除以 √64 = 8 再 softmax
(35.9, 2.3, −5.1)(1.0000, 0.0000, 0.0000)(0.9794, 0.0147, 0.0059)

不缩放时，输出是 (1, 0, 0) ——一个词的权重是 100%，其余全是 0%。这对训练是灾难：权重为 0 意味着"这条路完全没被使用"，反向传播时梯度也几乎为 0（softmax 在饱和区的导数趋近于 0），模型学不到东西，就像你被锁死在"只读一本书"的状态，再也听不进别的意见。缩放之后，权重分布温和得多，每条路径都有梯度流过，模型才能同时比较"多看谁一点"的细微差别。

可以再补一个几何直觉：softmax 对"差距"敏感，而对"整体大小"不敏感——给所有分数同时加上一个常数，softmax 结果不变（分子分母的 ec 约掉了）。但乘法的缩放会真实改变差距：分数越大，相对差距被指数放得越大。√d_k 缩放的本质就是把"差距"维持在 softmax 最敏感、梯度最充足的舒适区。

一句话记住

除以 √d_k 不是为了让数字好看，而是为了把 softmax 留在"能学到东西"的温和区间。维度越高，这个缩放越不可缺少。

3.7 对照原论文：这就是公式本身

把刚才手算的四步压缩成一行，就是 Vaswani 等人在 2017 年论文《Attention Is All You Need》中的公式（论文第 3.2.1 节，"Scaled Dot-Product Attention"）：

Attention(Q, K, V) = softmax( QKᵀ / √d_k ) V
公式里的符号对应我们手算的哪一步本例数值真实模型中的形状
QKᵀ第 1 步：每个 Query 点乘每个 Key3×3 原始分数表[n × n]，10 词时是 10×10
/ √d_k第 2 步：除以缩放因子÷ 1.4142÷ √64 = 8
softmax(·)第 3 步：逐行归一化为权重权重矩阵 A（行和=1）[n × n]，每行和为 1
(·)V第 4 步：加权混合 Value输出 O[n × d_v]，10×64

原论文还对比过另一种注意力（加性注意力，additive attention），结论是缩放点积注意力效果相当但快得多、省内存——因为整个计算就是两次矩阵乘法，而矩阵乘法是 GPU 最擅长的事。这也是为什么"注意力"能扛起现代大模型：它不仅有效，而且天生为并行计算设计。回想第 1 章 RNN 的串行瓶颈：QKᵀ 把"每个词看每个词"的所有比较一次性算完，没有任何排队。

3.8 读懂注意力热力图

研究者和工程师最常用的"注意力透视仪"是热力图（heatmap）：把权重矩阵 A 画成一张格子图，格子颜色越深，权重越大。约定俗成的读法：

  • 行 = 谁在提问（Query 来自哪个词）；列 = 看谁（Key 来自哪个词）；
  • 每一行是一组 softmax 权重，所以每一行的格子加起来恒等于 1（列方向没有这个性质）；
  • 第 i 行第 j 列的深色格子读作："理解第 i 个词时，模型分了很多注意力给第 j 个词"。

真实训练出来的注意力长什么样？

上面的例子里权重是我们手工设计的。真实模型训练之后，热力图常常会出现几种非常有"语言学味道"的模式，你在 3.10 节的演示和第 4 章的多头演示里都能试着找一找：

  • 对角线模式：每个词最关注自己。这在底层很常见——先把自己"扶正"再说。
  • 指代模式：代词（"它""她"）那一行，深色格子落在被指代的名词上。这是注意力最经典的本事。
  • 邻居模式：深色格子集中在对角线附近——某些头只关心"前一个词/后一个词"，承担了类似 n-gram 的局部工作。
  • 分隔符模式：大量格子挤在句首符号或标点那一列。这通常是模型没找到明确关注对象时的"默认停靠位"，不必过度解读。
  • 长程搭配：动词跨过一长串修饰语，把注意力准确地投给它的主语或宾语——这正是 RNN 做不到、注意力一做就成的长程依赖。

警示：注意力权重 ≠ 解释

看到"猫关注了爱"，可以直觉地理解为"模型认为两者相关"，但学术界对"注意力权重能否当作模型决策的解释"有持续争论（有论文专门论证 attention is not explanation）。权重只是中间计算的一环，经过后续多层变换后，它对最终输出的真实贡献未必和权重数字成正比。读热力图时把它当作线索而不是证据。

3.9 自注意力与交叉注意力（预告）

本章算的例子有个特点：Q、K、V 全部来自同一个句子——"我 爱 猫"的词互相看彼此。这叫自注意力（Self-Attention），是编码器和 GPT 式解码器里的主力。

但注意力机制本身并不要求三方同源。在机器翻译的解码器里（详见第 6 章），会出现另一种用法：Query 来自正在生成的译文（比如已经生成的 "I love"），Key 和 Value 来自编码器处理完的原文（"我 爱 猫"）。直觉上就是：译文每生成一个词，都拿着自己的问题去查原文这座"图书馆"，决定该参考原文的哪几个词。这叫交叉注意力（Cross-Attention）——Q 和 K/V 来自两个不同的序列。计算流程一模一样，仍然是 softmax(QKᵀ/√d_k)V，只是 Q 的行数和 K/V 的行数可以不同（输出长度跟随 Q）。

另外还有一个重要变体：生成式模型（GPT 类）做自注意力时，不允许词"偷看"后面的词，需要给注意力矩阵的右上角打上 −∞ 的掩码再 softmax。这就是因果掩码，留到第 6 章详解。

类型Q 来自K、V 来自典型用途
自注意力（Self-Attention）句子自己句子自己理解一句话内部的关系（本章）
掩码自注意力（Masked）句子自己句子自己，但只能看左边GPT 式逐词生成（第 6、8 章）
交叉注意力（Cross-Attention）译文（解码器）原文（编码器的输出）翻译时对齐原文（第 6 章）

三者的计算公式完全一样，变的只是 Q、K、V 的来源和可见范围。学会一个，就学会了全部。

3.11 一次注意力的计算量有多大？

结束本章前，感受一下规模。QKᵀ 是 [n×d_k] × [d_k×n]，大约 n²·d_k 次乘加；AV 同样是 n²·d_v 量级。注意力主体的计算量随句子长度 n 平方增长：

n²
权重矩阵的格子数：句子 2 倍长，格子 4 倍多
2 次
大矩阵乘法：QKᵀ 与 A·V，GPU 的最爱

n = 100 时格子有 1 万个，毫无压力；n = 100 万（百万词上下文）时格子有 1 万亿个，光存这张权重表就要 TB 级内存。这就是为什么长上下文是 Transformer 的"阿喀琉斯之踵"，也是 FlashAttention、稀疏注意力等现代技术（第 9 章）要解决的问题。但在本书的绝大部分例子里，n 都很小——理解机制本身，3 个词就够了。

3.12 本章小结

  • 注意力 = 可微分的软查询：Query 是问题，Key 是标签，Value 是内容；按问题与标签的匹配度（点积）分配比例，混合内容。
  • Q、K、V 同源：都来自输入矩阵 X，各乘一个可学习权重矩阵，相当于每个词戴上三顶帽子扮演三种角色。
  • 四步流程：QKᵀ 算分数 → 除以 √d_k 缩放 → 逐行 softmax 得权重矩阵 A（每行和为 1）→ A·V 加权混合输出。
  • √d_k 的作用：d_k 维随机向量的点积方差是 d_k，不缩放会让 softmax 饱和、梯度消失，模型无法训练。
  • 热力图读法：行是提问者、列是被看者，每行和为 1。
  • 自注意力 vs 交叉注意力：同源是自注意力；Q 与 K/V 来自不同序列是交叉注意力（翻译解码器用）。
  • 3.5 节的「我 爱 猫」手算例子是本讲的"标准曲"，建议不看答案能独立复算。

常见误区

  • 误区 1："注意力就是选最重要的那个词。"错。注意力是软性的加权混合，不是取最大值。softmax 输出的是比例，输出向量为所有词 Value 的加权和，哪怕权重只有 0.05 的词也贡献了一份内容。
  • 误区 2："Q、K、V 是三份不同的输入数据。"错。它们是同一个输入 X 乘三个不同权重矩阵得到的三种投影。数据只有一份，角色有三种。
  • 误区 3："softmax 对整个矩阵一起做。"错。softmax 是逐行独立的：每个 Query 各自分配自己那 100% 的注意力预算。列方向不要求和为 1。
  • 误区 4："权重最大的格子就是'答案'。"权重只是"参考比例"，不是分类结果。而且一个注意力头只看一种"相关"，多种关系（指代、语序、搭配）要靠下一章的多头机制分工捕捉。
  • 误区 5："√d_k 是经验拍出来的常数。"它有明确的方差论证支撑（3.6 节），换成别的维度就要换别的缩放因子。

3.13 常见问题 FAQ

FAQ 1：Q、K、V 三个矩阵是怎么来的？是训练出来的吗？

是。WQ、WK、WV 是模型的可学习参数：初始化时是随机数，训练过程（第 7 章）里梯度下降把它们一步步调成有用的样子，训练完成后就固定下来。而 Q、K、V 本身不是参数，是用同一份输入 X 分别乘这三个矩阵算出来的投影——数据只有一份，角色有三种（3.3 节的"三顶帽子"）。所以准确的说法是：矩阵是学出来的，Q/K/V 是每次前向传播时临时算出来的。

FAQ 2：为什么 Q 和 K 相乘（点积）就能代表"相关性"？

点积在几何上等于两向量长度之积再乘夹角余弦，所以它度量的本质是方向有多一致：同向最大、垂直为零、反向为负。把注意力里的"相关性"定义成"Q 指向的方向与 K 指向的方向有多重合"就非常自然——训练的任务恰好是把 WQ、WK 调成"该互相寻找的词在这个空间里方向对齐"。另外点积只是一串乘加，是 GPU 最擅长的运算（3.5 节开头）。当然，"方向相似"只是相关性的一种定义，这正是下一章要用多个头并行多种标准的原因。

FAQ 3：注意力权重能当成模型决策的解释吗？

不能简单地当。权重只是整条计算链的中间一环——它后面还要乘 V、再过 W_O、残差、FFN 和后续很多层，某个权重很大不代表它对最终输出的贡献就大；学术界甚至有论文专门论证 "attention is not explanation"。正确的用法是把热力图当作线索：它能提示"模型可能在利用什么关系"，帮你提出假设，但要验证因果还得靠干预实验（比如遮住某个词看输出变不变）。3.8 节的警示框说的就是这个分寸。

FAQ 4：序列太长时注意力会怎么样？有什么办法？

注意力权重矩阵有 n² 个格子，计算量和内存都随序列长度平方增长（3.11 节）：1 万词约 1 亿个格子还能忍，100 万词就是 1 万亿个格子，光存权重表就要 TB 级内存。这是 Transformer 的"阿喀琉斯之踵"。现代对策主要有几路：FlashAttention（不改变数学结果，只重排内存读写来省显存、提速）、稀疏/滑窗注意力（每个词只看局部或少数关键位置）、以及各种低秩近似。第 9 章会展开讲这些技术。

自测 1：若 d_k 从 64 变成 256，缩放因子 √d_k 怎么变？不调整会发生什么？

√64 = 8，√256 = 16，缩放因子翻倍。如果维度变成 256 却仍除以 8，点积分数的典型幅度会比预期大一倍，softmax 输入偏大，输出权重更尖锐（更接近赢家通吃），梯度变小，训练会变慢甚至不稳定。缩放因子必须跟随 d_k 一起更新。

自测 2：在 3.5 节的例子里，"爱"那一行的原始分数是 (0, 1, 0.5)。如果不对第 2 步做缩放（即不除以 √2），softmax 后的三个权重大约会怎么变？

不缩放时 softmax 的输入是 (0, 1, 0.5)：e⁰=1、e¹≈2.718、e⁰·⁵≈1.649，和≈5.367，权重≈(0.186, 0.506, 0.307)。缩放后是 (0.2246, 0.4555, 0.3199)。可见不缩放会让权重更"尖锐"——最大者份额更大（0.506 vs 0.4555），最小者份额更小（0.186 vs 0.2246）。维度再高几个数量级，就会尖锐到 (1, 0, 0)，进入饱和区。

自测 3：注意力权重矩阵 A 的形状由什么决定？如果句子从 3 个词变成 10 个词，A 和输出 O 的形状各是多少（设 d_v = 2）？

A = softmax(QKᵀ)，Q 和 K 都是 [n × d_k]，所以 A 是 [n × n]——边长等于词数。10 个词时 A 是 [10 × 10]；O = A·V，V 是 [10 × 2]，所以 O 是 [10 × 2]。这也解释了注意力随句子长度的开销：权重矩阵有 n² 个格子，句子翻倍，格子数变 4 倍——这是长文本处理的核心瓶颈之一（第 9 章会讲现代对策）。

自测 4：3.5 节中"我"的输出是 (0.7141, 0.5928)，它约等于哪三个向量的什么组合？为什么输出一定落在"由 V 的行向量围成的凸包"里？

输出 = 0.4072×(1,0) + 0.2859×(0,1) + 0.3069×(1,1)，即三个 V 行向量的加权平均。因为权重非负且和为 1，输出是 V 各行的凸组合——几何上必然落在三个点围成的三角形内部（含边界）。这说明注意力本身"不会创造新内容"，它只是混合已有内容；真正产生新特征的工作交给后面的前馈网络（第 5 章）。
