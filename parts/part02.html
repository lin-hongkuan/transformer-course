第 2 章 · 词嵌入与位置编码

把单词变成坐标，再把顺序写进向量

计算机只认识数字，而语言是文字。这一章解决 Transformer 的「入口问题」：怎么把「国王」「苹果」这样的词变成可以加减乘除的向量？又怎么让模型知道「狗咬人」和「人咬狗」不是同一句话？学完你会亲手算出词向量之间的经典关系式，也会看懂位置编码那两条看似神秘的正弦公式。

在 第 1 章 里我们看到，RNN 因为「一次只能读一个词」而输掉了比赛，Transformer 的答案是一口气把整句话同时读进来。但这句话里有两个词值得追问：什么叫「读进来」？以及，「同时」会不会丢掉顺序？这一章的两大部分恰好就是这两个问题的答案：

  • 词嵌入（word embedding）：把每个词翻译成一串数字——一个向量。翻译得好，意思相近的词在数字空间里就离得近。
  • 位置编码（positional encoding）：既然所有词同时进入模型，模型本身看不到顺序，那就人为地给每个位置发一张「座位号」，并把座位号也写成向量，加到词向量上。

我们先从「词怎么变成数字」讲起。

2.1 第一步：把句子切成 token（词元）

模型不认识「句子」，只认识一个词表（vocabulary）——一本事先编好的「词典」，里面登记了模型认识的全部基本单位。每个基本单位叫一个 token（词元）。处理任何一句话的第一步，就是把句子切成一串 token，再查词表换成编号：

"我爱学习" → ["我", "爱", "学习"] → [312, 4901, 7635]

方括号里的数字就是 token 在词表里的「页码」。页码本身没有任何含义——312 号词和 313 号词没有任何特殊关系，就像词典第 312 页和第 313 页之间没有「意思更近」这回事。这一点很快会很重要。

一个现实问题：英语里 play、plays、played、playing 算不算四个词？如果算，词表会爆炸，而且很多低频词根本学不到足够的知识。现代模型的做法叫 BPE（Byte Pair Encoding，字节对编码）：把常见的词保留为完整 token，把不常见的词拆成「词根 + 词缀」这样的片段，例如 unhappiness 可能切成 un + happi + ness 三块。这样用一个不大不小的词表就能拼出几乎所有词。你只需要记住一句话：BPE 让模型既能覆盖生僻词，又不用背下整个语言的全部单词。细节不影响本章理解，我们先往前走。

词表到底有多大？

以经典模型 BERT base 为例，它的词表有 30522 个 token。这个数字会在本章后面反复出现：它决定了下面 one-hot 向量的长度，也决定了词嵌入矩阵的行数。

2.2 one-hot：最直白的办法，也是最坏的办法

拿到编号之后，最直接的数字化方案是 one-hot 编码（独热编码）：向量长度 = 词表大小，词出现在哪个编号，哪一位就是 1，其余全是 0。

假设玩具词表只有 6 个词：[我, 你, 爱, 猫, 狗, 跑]，那么：

词编号one-hot 向量
我0[1, 0, 0, 0, 0, 0]
猫3[0, 0, 0, 1, 0, 0]
狗4[0, 0, 0, 0, 1, 0]

这个方案有两个致命问题，每一个都值得停下来想清楚。

问题一：维度灾难——向量长得离谱

BERT 的词表是 30522 个词，也就是说每个词都要用一个 30522 维的向量来表示，而且其中 30521 个数字都是 0。这好比为了报一个手机号，你打印了一本三万页的书，只在某一页画一个勾。内存浪费之外，更实际的问题是：词表有 3 万行，嵌入矩阵就有 3 万行，任何计算都会被这个巨大而稀疏的表示拖累。这种「维度极高、内容几乎全空」的困境就叫维度灾难（curse of dimensionality）。

问题二：所有词之间的距离都一样

这是更深的问题。我们来算一算「距离」。两个向量之间的欧氏距离（就是直尺量的直线距离）公式是：

距离(a, b) = √( (a1−b1)² + (a2−b2)² + … + (an−bn)² )

代入上面的「猫」和「狗」：两个向量只有第 3、4 位不同（一个是 1,0，另一个是 0,1），其余全是 0，所以：

距离(猫, 狗) = √( (0−0)² + … + (1−0)² + (0−1)² + … ) = √(1+1) = √2 ≈ 1.414

再算「猫」和「我」：同样是两个 1 出现在不同位置，答案还是 √2。事实上，任何两个不同的词，one-hot 距离都是 √2。「猫」和「狗」是近亲，「猫」和「 democracy（民主）」八竿子打不着，但在 one-hot 世界里它们一模一样远。这就好比一张地图上所有城市的两两距离都相等——这张地图没有任何导航价值。

一句话记住 one-hot 的死穴

one-hot 只回答了「这个词是第几号」，完全没有回答「这个词是什么意思」。我们要的不是身份证号，而是能反映语义关系的「坐标」。下面这个交互演示会让你直观看到「好坐标」长什么样。

2.3 分布式词嵌入：给每个词一个「坐标」

解决方案叫 词嵌入（word embedding），也叫分布式表示（distributed representation）。想法一句话就能说完：不用 30522 维里只亮一盏灯，而是用几百个维度一起「调配」出一个词。每个维度不再对应某个具体的词，而是对应某种难以名状的「语义成分」——你可以把其中一个维度粗略想象成「皇室程度」，另一个想象成「动物性」，还有一个是「大小」……真实的维度没有这么干净的人类标签，但道理一样。

于是「国王」可能变成：

国王 → [0.9, 0.8, −0.1, …, 0.3] （d_model = 512 维）

在原始 Transformer 论文里，每个词被表示成 d_model = 512 维的稠密向量——30522 维的稀疏 one-hot 被压缩成了 512 维的「坐标」。为什么这叫「分布式」？因为一个词的意思不再由某一个位置承担，而是分布在这 512 个数字的联合模式里；反过来，每个维度也参与描述成千上万个词。

这些坐标从哪来？

不是人工标的，而是学出来的。训练开始时，每个词的向量是随机数；训练中模型每猜错一次下一个词，就微调一下相关词的坐标。几十亿句话读下来，「猫」和「狗」因为经常出现在相似上下文（「我家__很可爱」）而被推到一起，「猫」和「汽车」则被推开。语言学家 J.R. Firth 1957 年的名言是这个过程的最佳注脚：

You shall know a word by the company it keeps.（看一个词常和哪些词作伴，就知道它的意思。）

工程上，词嵌入就是一张 30522 × 512 的大表 E：查「编号 312」就是把第 312 行取出来。取行这个操作，数学上等价于用 one-hot 向量去乘 E——one-hot 里那个 1 会「挑出」对应的一行。所以 one-hot 并没有被抛弃，它退居幕后，成了查表的钥匙。

2.4 嵌入的几何魔法：国王 − 男人 + 女人 ≈ 王后

词嵌入最著名的一个现象是：词之间的「关系」对应空间里有方向的「位移」。从「男人」走到「女人」的那一段位移，和从「国王」走到「王后」的位移几乎平行且等长——因为它们编码的都是「换掉性别」这件事。写成算式就是著名的：

国王 − 男人 + 女人 ≈ 王后

这不是比喻，是可以动手算的向量加减。我们用一组刻意设计的 2 维小数字完整算一遍（真实嵌入是 512 维，但算术完全一样）。假设：

词2D 坐标坐标的含义（这一行是编出来帮助理解的）
男人[2, 0]第 1 维 ≈ 男性度
女人[0, 0]把「女性」放在原点上，方便算
国王[2, 5]第 2 维 ≈ 皇室度
王后[0, 5]女性 + 皇室

向量加减是逐分量进行的，一步一步来：

第 ① 步：国王 − 男人 = [2, 5] − [2, 0] = [0, 5]　（「国王身上去掉男性成分」）
第 ② 步：[0, 5] + 女人 [0, 0] = [0, 5]　（「再加回女性成分」）
查表：[0, 5] 正好是 王后 的坐标 ✓

在实际模型里，算出来的结果不会恰好等于某个词的坐标，而是落在某个坐标附近——这时就在词表里找「离它最近的词」，那个词往往就是「王后」。「最近」通常用余弦相似度（cosine similarity）衡量：看两个向量方向的夹角而不是绝对距离，夹角越小越相似。你只要知道它是「方向是否一致」的度量即可，公式细节不影响本章理解。

为什么要讲这个例子？

它说明嵌入空间不是杂乱的点云，而是有结构的几何体：方向有意义，位移有意义。这意味着模型可以通过「向量运算」来做类比推理——这是后面注意力机制能在向量之间「传递信息」的地基。请记住这种几何直觉，第 3 章的注意力分数本质上也在这里发生。

2.5 新问题：Transformer 看不出词的顺序

词嵌入解决了「词义」问题，却暴露了一个新问题。回忆第 1 章的结论：Transformer 把整句话的词同时送入模型，不像 RNN 那样一个接一个。这样做虽然快，但模型收到的其实是一袋词向量，而不是一串词向量——它不知道谁先谁后。

顺序重不重要？看这两句话：

「狗咬人」 ≠ 「人咬狗」

两句话的 token 完全相同，词嵌入也完全相同，只是把词的位置调换了一下，意思却天差地别——前一句是日常新闻，后一句是要上头版的新闻。再看一个更微妙的例子：「他买了苹果和手机」vs「他买了手机和苹果」，词袋模型眼中它们一模一样。所以：

核心矛盾

自注意力（第 3 章的主角）本身对顺序是「盲」的：把输入的词任意打乱，注意力算出来的关系不变。如果我们不主动把位置信息塞进向量，模型永远分不清「狗咬人」和「人咬狗」。

怎么办？思路朴素得可爱：给每个位置编一个向量，加到词向量上。最终送入模型的向量是：

输入向量(pos, 词) = 词嵌入(词) + 位置编码(pos)

两个都是 512 维向量，逐分量相加，结果还是 512 维。词向量回答「我是谁」，位置向量回答「我坐第几排」，加起来之后的向量同时携带两种信息。接下来的全部问题只剩一个：位置编码 PE(pos) 这 512 个数怎么填？

2.6 正弦位置编码：给每个位置一座「多频率钟表」

先排除两个天真的方案

在给出答案之前，先看看直觉方案为什么不行，这样标准答案就不会显得突兀：

  • 方案 A：直接填 0, 1, 2, 3, …。一句话有 500 个词，位置数就到 500。数字太大、没有上界，和词向量（数值在 ±1 附近）根本不在一个量级，会把词义信息淹没；而且训练时只见过 512 以内的位置，推理时来一句 1000 词的，模型当场没见过世面。
  • 方案 B：填 pos / 最大长度，把位置压到 0~1 之间。问题是「相邻两个位置的差」随句子长度变化：10 个词的句子里差 0.1，1000 个词的句子里差 0.001。「相距 3 个位置」这个关系变得不稳定，而语言里最重要的恰恰是这种相对距离。

我们需要一种编码，满足三条：① 每个位置独一无二；② 数值有界，不随句长爆炸；③ 任意两个位置的相对距离可以被稳定地读出来。Vaswani 等人 2017 年给出的答案，是用一组频率各不相同的正弦、余弦波：

PE(pos, 2i) = sin( pos / 100002i/d )
PE(pos, 2i+1) = cos( pos / 100002i/d )

先别被公式吓到，把它拆开读：

  • pos 是位置序号：第 0 个词、第 1 个词、第 2 个词……
  • i 是维度编号的「对数」：512 维被分成 256 对，第 i 对包含第 2i 维（填 sin）和第 2i+1 维（填 cos）。d 就是 d_model = 512。
  • 分母里的 10000^(2i/d) 控制频率：i 越小，分母越接近 1，波形随 pos 变化越快（高频）；i 越大，分母最大可达 10000，波形极其缓慢（低频）。

直觉一：一排快慢不同的钟表指针

想象墙上有 256 座钟：第一座秒针转得飞快，第二座慢一半，……，最后一座一万步才挪一格。每个位置 pos 对应的「512 维编码」，就是此刻 256 座钟所有指针的横坐标（sin）与纵坐标（cos）拼起来的快照。因为每座钟转速都不同，不同时刻的快照绝不重复——这保证了「每个位置独一无二」。

直觉二：连续版的二进制计数

再换一个角度。用二进制给位置编号：0=000, 1=001, 2=010, 3=011, 4=100……观察每一位的「翻动频率」：最低位每步翻一次（0,1,0,1…），次低位每两步翻一次（0,0,1,1…），再高位每四步翻一次——每一位就是一个固定频率的方波。正弦位置编码干的是同一件事，只是把生硬的方波换成了光滑的正弦波：最低几维是高频正弦（变化快），最高几维是低频正弦（变化慢）。光滑的好处是可微分、对神经网络的梯度训练友好，而且取值天然落在 [−1, 1]，自动满足「有界」。

亲手算一遍：PE(pos = 1) 的前几维

设 d = 512，取 pos = 1，算前 4 维（i = 0 和 i = 1 两对）。记住两个数：sin(1) ≈ 0.841，cos(1) ≈ 0.540。

维度i分母 10000^(2i/512)公式代入结果
PE(1, 0)010000⁰ = 1sin(1 / 1)0.841
PE(1, 1)010000⁰ = 1cos(1 / 1)0.540
PE(1, 2)110000^(2/512) ≈ 1.036sin(1 / 1.036) = sin(0.965)0.821
PE(1, 3)1≈ 1.036cos(1 / 1.036) = cos(0.965)0.569

所以位置 1 的编码开头长这样：PE(1) = [0.841, 0.540, 0.821, 0.569, …]。注意第二维对（i=1）的分母只比 1 大一点点——因为指数 2/512 很小，频率衰减在开头是非常缓慢的；要到 i 接近 256 时，分母才会逼近 10000。这种「指数级拉开的频率梯度」正是设计的精髓。

为什么正弦编码能「外推」到没见过的长句子？

这是它最值钱的一条性质。关键在于一条高中三角恒等式：

sin(a + b) = sin a · cos b + cos a · sin b
cos(a + b) = cos a · cos b − sin a · sin b

把 a 换成「pos 处的相位」、b 换成「k 步之后的相位增量」，这两条公式说的就是：PE(pos + k) 可以写成 PE(pos) 各分量的线性组合，而且组合系数只取决于 k，不取决于 pos。换句话说，「往后挪 k 格」这个操作，在编码空间里是一个固定的线性变换（一次旋转）。

这对模型意味着：只要它在训练时学会了「关注前方第 3 个词」这种相对模式，这个模式对任何绝对位置都成立，对训练时从没出现过的超长句子也同样成立——因为 sin、cos 函数对任意大的 pos 都有定义，波形照常延伸。这就是为什么原论文说正弦编码「可能让模型外推到比训练时更长的序列」。

2.7 另一条路线：可学习的位置编码

正弦编码是「手工设计」的，参数为零。另一条更直接的路线是：位置编码也做成一张可学习的表，比如「最多 512 个位置 × 512 维」，和词嵌入一样随机初始化、随训练一起更新。BERT 用的就是这种做法（BERT base：词表 30522、隐层 768 维、最大位置 512）。

0正弦编码的可训练参数量 —— 公式写死，不占模型容量
512×768BERT base 可学习位置表的参数量（≈ 39 万）

两条路线的取舍很直白：

  • 正弦编码：不占参数、理论上支持任意长度、自带「相对位置 = 线性变换」的优良结构；代价是形式固定，模型没有调整余地。
  • 可学习编码：灵活，模型可以为不同位置学到任意模式；代价是有硬上限（BERT 超过 512 个 token 就没位置可查了），且原论文的实验表明两者效果几乎打平——这也是 Vaswani 等人最终选择正弦方案的原因。

2.8 现代做法预告：RoPE（旋转位置编码）

今天的主流大模型（LLaMA 系列等）普遍采用 RoPE（Rotary Positional Embedding，旋转位置编码）。它的思想可以一句话概括：不再把位置向量「加」到词向量上，而是按位置把 Query、Key 向量成对地「旋转」一个角度，位置差多少就转多少，让相对位置信息在注意力点积里自然浮现。直觉上，它是正弦编码「位置差 = 固定旋转」这条性质的极致发挥。完整的推导和图示我们放到 第 9 章，届时你已掌握注意力机制，会看得非常顺。

2.9 本章全景：一句话从文字到模型入口

把本章所有零件串起来，Transformer 入口处的数据流是这样的：

文字 → 切 token → 查词表得编号 → 查嵌入表 E[30522×512] 得词向量 + 位置编码 PE(pos) → [序列长 × 512] 的输入矩阵

这个「序列长 × 512」的矩阵，就是下一章注意力机制要处理的原料。每个词此刻既知道自己「是谁」（词义），也知道自己「在哪」（位置），接下来该让它们互相打听了——这就是注意力的故事。

2.10 小结

  • token 是模型认识语言的基本单位；BPE 用「词根+词缀」的拼装思路控制词表大小（BERT base：30522 个 token）。
  • one-hot 编码有两个死穴：维度高达词表大小（维度灾难），且任意两词的距离恒为 √2，完全不含语义。
  • 词嵌入把每个词变成 d_model=512 维的稠密「坐标」，由训练自动学出；语义相近 ⇒ 空间相近，「国王−男人+女人≈王后」展示了嵌入空间的方向与位移都有意义。
  • 自注意力对顺序天然无感，必须显式注入位置信息：输入 = 词嵌入 + 位置编码。
  • 正弦位置编码用一组频率指数递减的 sin/cos 波为每个位置生成「多频率钟表快照」；它无参数、有界、支持外推，且 PE(pos+k) 是 PE(pos) 的线性变换，天然携带相对位置信息。
  • 可学习位置编码更灵活但有长度上限，效果与正弦方案接近；现代模型多用 RoPE（详见第 9 章）。

常见误区

误区一：「词向量是人工程标注的语义特征。」不是。坐标完全由训练目标（预测上下文）自动塑造，所谓「皇室度」「男性度」只是事后的粗略解读，单个维度通常没有干净的人类含义。

误区二：「位置编码告诉模型『这是第 7 个词』这个绝对事实就够了。」不够。语言理解依赖的主要是相对位置（「主语前面那个词」「相隔三个词」），正弦编码的价值恰恰在于让相对位置可以被线性读出。

误区三：「词嵌入 + 位置编码会把两种信息混成一团。」不会。512 维空间足够大，模型可以在训练中学会把「词义方向」和「位置方向」分离开使用；加法在这里是信息叠加，不是信息覆盖。

2.11 自测题

为什么 one-hot 编码中「猫」和「狗」的距离，与「猫」和「民主」的距离相等？这说明什么问题？

因为 one-hot 向量中任意两个不同的词，1 出现的位置都不同，欧氏距离恒为 √(1²+1²) = √2。距离与语义完全脱钩：one-hot 只记录了「词的编号」，没有记录「词的意思」。这说明 one-hot 不能作为语义表示，我们需要能让「近义词距离近」的稠密向量——词嵌入。

设「巴黎」的 2D 坐标是 [3, 4]，「法国」是 [3, 1]，「意大利」是 [5, 1]。按 king−man+woman 的思路，「巴黎 − 法国 + 意大利」应该接近哪个词？

逐分量计算：[3,4] − [3,1] = [0,3]（「巴黎去掉法国属性」）；[0,3] + [5,1] = [5,4]。坐标 [5,4] 表示「意大利 + 首都属性」，对应的词应该是「罗马」。这个小练习说明：只要嵌入空间结构良好，类比推理就是纯粹的向量加减。

正弦位置编码为什么能外推到比训练时更长的序列？可学习位置编码为什么不行？

两点原因：① sin/cos 对任意大的 pos 都有定义且取值有界，长句子的编码照常生成；② 由三角恒等式，PE(pos+k) 是 PE(pos) 的线性变换，模型学到的「相距 k 位」的相对模式与绝对位置无关，因此迁移到更长的序列依然成立。可学习编码则是一张固定行数的表（如 BERT 的 512 行），超出表长的位置没有任何向量可查，更谈不上外推。
